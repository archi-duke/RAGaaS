## 1. 문제

연도·날짜가 그래프에 **조회할 수 있는 형태로** 없다.

| 형태 | 예 | 규모 (물리학사, 11/16) |
|---|---|---|
| 값 안에 섞임 | `수상함 → "노벨 물리학상 (1933년)"`, `강연 → "1908년 쾰른에서"` | 트리플 102개, 관계 18종 |
| 그래프에 없고 원문에만 | 『열과 일의 정밀측정』(1872), 마이컬슨-몰리 실험(1887) | 다수 (시간 질문 대부분) |
| 별도 값 노드 | `출생 → 1831년`, `사망 → 1894년` | 일부 인물만 |

**영향**

- 기간 질문을 조건으로 풀 수 없다 ("1930년대에 노벨상을 받은 인물", Q31). 에이전트가 `contains "193"` 같은 문자열 꼼수를 쓰거나 원문을 하나씩 읽는다.
- 같은 상이 연도별로 다른 값이 된다. `노벨 물리학상`, `노벨 물리학상 (1918년)`, `… (1933년)` … 로 나뉘어 "노벨상 수상자 전체" 조회가 어렵다.
  - 11/16 AI 추천이 이것들을 하나로 합치자고 했지만, 그러면 연도가 사라져 거절했다.
- "1872년에 저술한 책"(Q35)처럼 사건의 연도로 묻는 질문은 그래프 조회로 찾을 수 없다.

## 2. 선택지

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 진술 연도 (권장)** | 트리플(진술)에 연도를 붙인다: `(피르나우, 수상함, 노벨 물리학상)` + `meta:year 1933`. 값은 연도를 뺀 기본형으로 통일한다 | 상이 하나로 모인다. "어느 상을 언제" 짝이 유지된다. 지금 근거 청크 연결(진술 노드)과 같은 구조라 저장이 쉽다 | 질의 계획에 연도 조건을 추가해야 한다 |
| B. 엔티티 연도 속성 | `피르나우 수상_연도 1933` 같은 별도 트리플 | 구현이 가장 단순하다 | 상이 여러 개면 어느 상의 연도인지 짝이 끊긴다 |
| C. 사건 노드 | `수상_사건_17 {인물, 상, 연도}` (n-항 관계) | 표현력이 가장 크다 | 추출·질의·화면이 모두 복잡해진다. 지금 그래프 구조와 크게 다르다 |

**A 를 권한다.**

- 근거 청크 연결에 이미 진술 노드(`rdf:subject / predicate / object` + `meta:sourceNodeId`)를 쓰고 있어, `meta:year` 를 하나 더 다는 것으로 끝난다.
- 질의 계획에는 조건 하나에 `year` 를 붙이는 형태로 넣는다.

## 3. 안 A 상세

### 3.1 저장

```turtle
inst:피르나우 rel:수상함 inst:노벨_물리학상 .
stmt:abc rdf:subject inst:피르나우 ; rdf:predicate rel:수상함 ; rdf:object inst:노벨_물리학상 ;
         meta:sourceNodeId "청크ID" ; meta:year 1933 .
```

- 한 진술에 연도는 하나다. 같은 (s, p, o) 가 다른 연도로 두 번 나오면 진술 노드를 둘로 둔다 (예: 같은 상을 두 번 수상).
- `meta:yearText` 에 원문 표기를 보관한다 ("1868년", "1880년대 초"). 범위·대략값(`~1850s`)은 `meta:yearFrom` / `meta:yearTo` 로 둔다.

### 3.2 추출 (결정적 분리 + 추출 프롬프트)

1. **Y1. 결정적 분리** (정규화 단계, LLM 없음):
   - 값의 끝에 붙은 연도 패턴을 떼어 내 진술 연도로 옮긴다: `X (1933년)`, `X(1933)`, `1908년 쾰른에서` → 값 `쾰른`.
   - 지금 있는 102개 트리플은 재추출 없이 리플레이만으로 정리된다.
2. **Y2. 추출 프롬프트**: 트리플마다 문장에 연도가 있으면 `"year": 1872` 를 함께 내게 한다. "1872년 크뢰벨은 『열과 일의 정밀측정』을 저술했다" → `(크뢰벨, 저술함, 『열과 일의 정밀측정』, year=1872)`.
   - 연도가 없는 문장에는 넣지 않는다. 지어내지 않는다.
   - 한 문단 안에서 앞 문장의 연도를 이어받는 것은 하지 않는다 (오류 위험).
3. **Y3. 검증**: 연도는 1000~2100 정수만 받는다. 출생 이전·사망 이후 연도는 경고만 한다 (D1 방향 검증처럼 제안으로).

### 3.3 질의 (query_plan 확장)

조건(leaf)에 `year` 를 붙인다.

```json
{"kind": "Person",
 "where": {"path": "수상함", "op": "contains", "value": "노벨", "year": {"gte": 1930, "lte": 1939}},
 "return": ["수상함"]}
```

- 컴파일: 조건의 트리플에 진술 노드 조인 + `FILTER(?year >= 1930 && ?year <= 1939)`.
- 연도가 없는 진술은 연도 조건이 있으면 **만족하지 않는다**. 결과의 `conditions` 에 "연도 정보 없는 트리플 N개 제외" 를 보고해 조용히 빠지지 않게 한다.
- `return` 의 값에는 연도를 붙여 준다: `"수상함": ["노벨 물리학상 (1933)"]`.
- `describe_kb` 는 경로마다 연도가 있는 진술의 비율(`year_coverage`)을 보여 준다.
- `describe_entity` 의 out / in 항목에도 `year` 를 넣는다.

### 3.4 내부 검색

질의 계획 LLM 프롬프트에 연도 조건 형식을 추가한다 ("1930년대" → `{"gte": 1930, "lte": 1939}`).

## 4. 단계와 확인

| 단계 | 내용 | 확인 (좁은 확인) |
|---|---|---|
| Y1 | 결정적 분리 + 진술 연도 저장 + 리플레이 | 102개 중 분리 수, `노벨 물리학상` 값이 하나로 모이는지 |
| Y2 | 추출 프롬프트 + 재추출 | 시간 질문(temporal 5, Q31, Q35, Q36)의 근거 트리플에 연도가 붙는지 |
| Y3 | query_plan·describe·스킬에 연도 조건 | Q31 을 연도 조건 하나로 푸는지 |
| — | 최종 전체 평가 2회 | 기준 대비 |

비용: Y1 은 LLM 0. Y2 는 재추출 1회 (물리학사 GLM 기준 20~40분). Y3 는 코드만.

## 5. 위험

| 위험 | 대응 |
|---|---|
| 추출이 연도를 지어냄 | 문장에 숫자 연도가 있을 때만 받는다 (숫자가 원문에 있는지 검사) |
| 다른 사건의 연도가 붙음 ("1868년 회전원판 실험 … 같은 해 보정") | 같은 문장 안의 연도만 쓴다. '같은 해' 같은 지시 표현은 Y2 범위 밖이다 (원문 확인 규칙으로 보완) |
| 연도 조건 때문에 결과가 조용히 줄어듦 | 연도 없는 트리플 수를 결과에 보고한다 |
| 기존 값 규칙·병합과 충돌 | 분리는 값 규칙보다 먼저 한다. 병합 대상 이름에는 연도가 없게 맞춘다 |

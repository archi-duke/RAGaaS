## 1. 문제

질문의 표기가 그래프 값과 다르면 못 찾는다.

| 질문 | 그래프 값 | 실패 지점 |
|---|---|---|
| 핵폭틴 개방에 기여한 사람은? (오타) | 원자폭탄 개발 | 질문 분석이 오타를 그대로 엔티티로 → 에이전틱이 근거 없이 'QED' 로 해석 |
| 핵폭탄 개발에 기여한 사람은? (동의어) | 원자폭탄 개발 | 사전에 '핵폭탄↔원자폭탄' 없음 |
| 슈레딩거 방정식 (오타) | 슈뢰딩거 방정식 | 사전은 적재 때 만든 표기만 안다 |

원인:
- **용어 사전은 적재 때 만든 표기만** 안다 (한영·동의어). 오탈자는 못 찾고, 스키마 요약에 안 나오는 값(멤버 1명 경로 — `자문 → 원자폭탄 개발`)은 사전에 항목조차 없다.
- **영어 표기 대체 단계**(클라이언트 `terms_en` + 영어 임베딩)는 기준이 높아(0.80) 'atomic bomb development' 로도 후보가 안 나왔다.

## 2. 방식 비교 (실험, 2026-11-17)

물리학사 KB 그래프 라벨 926개, 질문어 20개 (오타 5 · 띄어쓰기 4 · 동의어·약어 8 · 영어 3). 정답 라벨을 1위로 찾은 수:

| 방식 | 오타 | 띄어쓰기 | 동의어·약어 | 영어 | 합계 | LLM |
|---|---|---|---|---|---|---|
| 용어 사전 (기존) | 0 | 4 | 3 | 3 | 10 | 적재 때 1회 |
| 자모 편집거리 | **5** | 4 | 2 | 0 | 11 | 없음 |
| 라벨 임베딩 근접도 | **5** | 3 | 3 | 1 | 12 | 없음 |
| LLM 교정·동의어 | 4 | 4 | **6** | 3 | 17 | 1회 |
| **합집합** | 5 | 4 | 8 | 3 | **20** | — |

- 자모 편집거리는 오타·띄어쓰기에 확실하다 (슈레딩거 0.056, 하이젠베르그 0.077). 뜻이 같은 다른 말은 모른다.
- 임베딩은 점수만으로 맞고 틀림이 갈리지 않는다 (정답 '핵폭탄→원자폭탄 개발' 0.44 < 오답 '빛알 가설→빛의 파동설' 0.61) → **확정에 쓰지 않는다**.
- LLM 은 동의어·약어에 강하지만 KB 의 실제 표기를 모른다 ('특수 상대성 이론' 으로 고쳐 '특수 상대론' 에 못 닿음) → LLM 이 낸 말을 다시 라벨에 맞춘다.

## 3. 설계 — 후보를 여러 방식으로 만들고, 맥락으로 고른다

### 3.1 후보 생성 (공통, `agent_query/fuzzy_match.py`)

- 대상: **그래프의 현재 값 라벨 전체** (사전이 아니라 — 재추출로 라벨이 바뀌어도 따라감).
- 자모 편집거리: 한글을 초·중·종성으로 풀어 편집거리, 라벨이 길면 가장 가까운 구간과 비교. 자모 절반 이상이 겹치는 라벨만 계산 (말당 약 0.14초).
- 라벨 임베딩: KB 임베딩 모델로 라벨을 1회 임베딩해 메모리에 두고(30분, 라벨 집합이 바뀌면 다시) 말 임베딩과 비교.
- **자동 확정은 자모 거리 0.2 이하 + 라벨 길이가 말의 2배 이하일 때만** (명백한 오타·띄어쓰기). 긴 설명형 라벨에 부분 일치로 확정하지 않는다. 나머지는 후보 (자모 0.45 이하, 임베딩 0.40 이상, 방식별 3개).

### 3.2 MCP — `lookup_values`

- 사전·링킹으로 못 찾은 말에 3.1 후보를 붙인다. 자동 확정은 `matches` (`via=fuzzy:<라벨>`), 나머지는 `suggestions` (`via=fuzzy|embedding|fuzzy+embedding`, `distance`·`similarity`).
- `query_plan` 은 그대로 엄격하다 — 값 표기를 서버가 몰래 바꾸지 않는다. 클라이언트가 후보에서 골라 계획에 쓴다.

### 3.3 Graph 필터 (내부 검색)

1. **질문 분석에 필드 2개** (추가 LLM 호출 없음): `corrected_query` (오타만 고친 질문, 없으면 null), `term_variants` (엔티티별 같은 대상의 다른 이름 4개까지 — 오타면 고친 철자를 맨 앞에).
2. 원래 말 + 동의어로 3.2 와 같은 값 찾기 → 자동 확정 라벨은 엔티티 링킹에, 자동 확정·후보 라벨은 **질의 계획 경로 힌트**(값이 맞는 경로를 계획 후보 앞에 — PR #68)에.
3. 문서 검색(보강·대체)은 교정 질문으로.
4. **해석을 드러낸다**: Execution Log `[해석]`, 결과 요약에 "질문 표기 해석: … — 이 해석으로 찾았음을 답변에 밝힐 것". 원래 말이 그래프에 그대로 있으면 동의어 해석은 힌트로만 쓰고 밝히지 않는다.

### 3.4 함께 고친 것

- `query_plan` 의 `contains` 가 값 목록을 받으면 OR (계획 LLM 이 힌트 값 둘을 목록으로 넣었는데 목록을 문자열로 바꿔 찾아 0건이 됐다).

## 4. 확인

| 질문 | 전 | 후 (2회) |
|---|---|---|
| 핵폭틴 개방에 기여한 사람은? | QED 로 오해석 (도모나가·슈윙거·파인만) | 보어·파인만, 해석 밝힘 |
| 핵폭탄 개발에 기여한 사람은? | 아인슈타인 | 보어·파인만 |
| 원자 폭탄 개발에 기여한 사람은? | 아인슈타인 | 보어·파인만 |
| 슈레딩거 방정식 / 하이젠베르그 / 빛알 가설 / 중력 법칙 / QED | — | 모두 정답 |

## 5. 한계·다음

- 실험은 한 KB·20개 말이다. 물리학사 평가에 오탈자·동의어 문항을 추가해 계속 측정한다.
- 에이전틱 필터가 근거 없는 해석을 세우는 문제('핵폭틴 개방 = QED')는 Graph 필터가 맞게 찾으면 드러나지 않지만, 규칙 보강은 별도.
- 임베딩 후보는 엉뚱한 것('볼타')도 섞인다 — 확정에 쓰지 않는 이유. 후보 수를 늘리지 않는다.

## D1. Milvus 초기화 후 복원 원칙 = 저장된 청크 재임베딩, 같은 node_id

- **결정**: 재업로드하지 않고 `/data/uploads/<kb>/<doc>_chunks.json` 을 다시 임베딩해 **같은 node_id** 로 넣는다 (사용자 승인한 Milvus 초기화 이후).
- **이유**: 그래프의 근거 청크 연결(`meta:sourceNodeId`)이 node_id 로 묶여 있어, 재업로드하면 그래프·청크 연결이 끊긴다.

## D3. 다양한 문서의 승격 = 시드 스키마 (자동 유도 단독 폐기)

- **문제**: 자동 유도가 '관련됨·소속' 같은 일반 동사 스키마를 만들어 검색에 쓸모가 없었다 (승격 전 8/39 → 자동 승격+재추출 12/39).
- **결정**: 사람이 핵심 관계 어휘(정의·방향 포함)를 시드로 주고, 기존 관계를 거기에 매핑한 뒤 정의 기반으로 재추출한다.
- **폐기**: 다양한 문서에 자동 유도 스키마만 쓰는 방식 (구조가 균질한 문서에는 여전히 유효).
- **참조**: PR #55 · 평가 README 3

## D4. 다단계 질문 = 홉별 결정적 체인(H)

- **결정**: LLM 이 홉 계획(관계·방향)만 세우고, 각 홉은 결정적 SPARQL 로 따라간다. 계획 관계가 0건이면 노드의 실제 관계 중 한 번 재선택.
- **폐기**: 다단계를 C(LLM SPARQL 생성)로 보내던 방식 — 다단계 0/10.
- **설계서**: `design-graph-multihop-chain.md` · PR #55

## D7. 재추출 시 domain 위반·근거 없는 트리플 제외 (P4)

- **결정**: 재추출 결과에서 주어 클래스가 관계 domain 과 다르면 버리고, 원문에 근거 없는 목적어도 버린다 (f7b442a, 27.0/39).
- **이유**: 잘못된 관계가 스키마 안 관계로 들어가면 검색이 오답을 확신한다.
- **나중에 드러난 대가**: 11/17 — 정의는 넓은데 domain 이 좁은 관계(`기반함`)의 사실이 조용히 버려짐 (`2026-11-17` D5).

## D2. 연도 = 진술(트리플)에 붙인다 (안 A)

- **문제**: 연도가 값에 섞이거나(`노벨 물리학상 (1933년)`) 원문에만 있어 "1930년대 노벨상" 같은 질문을 조건으로 풀 수 없음 (Q31·Q35·Q36).
- **결정**: 진술 노드에 `meta:year`(+ `meta:yearText`). 같은 (s, p, o) 라도 연도가 다르면 진술을 둘로.
  - Y1 결정적 분리 (LLM 없음): `X (1933년)`, `X, 1860년`, `1908년 쾰른 강연` 만. 범위·대략값·날짜 조각만 남는 경우는 그대로.
  - Y2 추출 프롬프트: 같은 문장의 연도만 `year` 로, 원문 한 문장에 연도와 주어·목적어가 함께 있을 때만 받는다.
  - Y3 query_plan 조건에 `year` (정수 또는 gte/lte). 연도 없는 진술은 연도 조건을 만족하지 않고, 그로 빠진 엔티티 수를 `adjustments` 에 보고.
- **폐기한 대안**: B 엔티티 연도 속성(`수상_연도`) — 상이 여럿이면 짝이 끊김. C 사건 노드(n-항) — 추출·질의·화면이 모두 복잡.
- **결과**: Q31 을 조건 하나로 해결 (슈뢰딩거·디랙·하이젠베르크). 별도 '수행_연도 → 1887년' 류 트리플이 진술 연도로 흡수돼 관계 트리플 1,437 → 1,247.
- **설계서**: `design/schema/design-year-attributes.md` · 브랜치 `feat/year-attributes`

## D5. 관계 domain 은 하나만 허용한다 (다중 domain 적용 안 함)

- **검토**: domain 을 여러 클래스로 허용하면 `기반함` 같은 관계를 정의대로 표현할 수 있다.
- **결정 (사용자)**: 적용하지 않는다.
- **이유**:
  - 목록만으로는 OR(이 중 하나)인지 AND(모두)인지 모호하다. 사용자 지적: "OR 가 아닌 AND로 해석해야 할 경우도 있잖아".
  - RAGaaS 는 엔티티가 클래스를 하나만 가진다 → AND domain 은 만족할 수 없다.
  - RDF 에서 `rdfs:domain` 여러 개는 교집합(AND) 의미라, OR 로 쓰면 TBox 의미가 틀어진다.
  - 영향 범위가 넓다 (추출 검사, 방향 교정·검증, 진단·추천, 체인, 편집기·그래프 화면, 외부 describe 계약).
- **대가**: 정의가 domain 보다 넓은 관계는 ① 정의를 domain 에 맞게 고치거나 ② 개별 사실을 @add 로 고정한다.
- **미결**: `기반함` 정의의 '실험' 문구를 domain 에 맞게 정리할지.

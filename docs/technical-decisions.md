# 기술 결정 이력

**목적**: "왜 이렇게 만들었나", "언제 왜 바꿨나" 를 주제별로 찾을 수 있게 모은 문서.
**갱신**: 2026-11-17 (문서 정리 — 경로 갱신)

## 읽는 법

- `docs/decisions/YYYY-MM-DD-decisions.md` 가 **날짜별 원본 로그**(D1~Dn)다. 이 문서는 그것을 **주제별로 묶은 색인**이다. 어긋나면 원본이 정본.
- 큰 구조 결정(저장소·서비스 경계·외부 계약)은 `docs/adr/` ADR 로, 날마다의 기술 선택은 `docs/decisions/` 로 남긴다. 이 색인은 둘을 함께 가리킨다.
- 2026-01~02 초기 설계는 `docs/_archive/arch-2026-02/` (ASR → QS → 후보 구조 CA → 결정) 와 블로그 4편이 원본이다 — 0장에 요약.
- 폐기된 결정은 지우지 않는다. **왜 폐기했는지가 다음 판단의 재료**다.
- 평가 수치의 출처는 `docs/datasets/physics-history/README.md` 항목 번호. 11/17 에 채점 기준이 바뀌었으니 수치 옆의 기준을 확인한다.
- 갱신은 `.claude/skills/decision-record` 스킬로 한다 (PR 단위 권장).

### 그래프 추출·검색 초기 결정 (블로그 2026-01-12 ~ 14)

**결정일**: 2026-01-13 ~ 14 (문서 추가일·본문 작성일)

**선택** (지금 구현과 다른 점은 9장 — 구현 기준으로 정리됨):
- 그래프 결과는 관심 엔티티 중심으로 (Focus & Expand) — 청크에 연결된 트리플 전체 수집 폐기 (노이즈 노드). Neo4j 경로에서 유효.
- 엔티티 추출은 spaCy 결과를 LLM 이 보충 (Expand Mode) — 한국어 고유명사 누락. spaCy 안에서만 고르는 Filter Mode 기각.
- Neo4j 적재는 항상 MERGE (`apoc.merge.relationship`) — 재업로드 중복 엣지. 유효.
- 병렬 나열 문장은 트리플 여러 개(Rule 6), 대명사 해소(Rule 5), 노이즈 predicate·조사 제거·S-P-O 중복 제거.
- 그래프 추출 섹션 6000/500 → 2500/1000, 역관계는 적재 시 만들지 않고 검색 시 양방향 — **둘 다 코드와 다름 (9장)**.
- BM25 = (선택) LLM 키워드 추출 + Kiwi 형태소 + BM25Okapi. 유효 (전체 청크 조회라 확장성 제약).
- 그래프 Fallback: Strict Mode 에서 키워드 regex fallback 금지 — 방향 무시 노이즈·환각. regex 제거는 유효, "빈 결과 반환" 은 이후 벡터 폴백 기본값으로 바뀜 (9장).
**참조**: `blog/llm-graph-noise-nodes.md` · `blog/graph-extraction-optimization.md` · `blog/bm25-keyword-search.md` · `blog/graph-fallback-policy.md`

## 1. 그래프 검색 (내부 파이프라인)

### 관계 SPARQL → 트리플 → 연결 청크 (Fast Path 이웃 전체 수집 폐기)

**결정일**: 2026-11-14

**선택**: 질문의 관계를 겨냥한 SPARQL 로 그 트리플만 찾고, 트리플에 연결된 청크로 답한다. A 결정적 매칭 → B 닫힌 집합 LLM 경로 선택. 추론 과정은 Execution Log 에 리포트.
**폐기한 것**: 앵커 주변 트리플 전체(79개)를 가져와 임베딩 점수로 청크를 고르는 Fast Path.
**왜 바꿨나**: 답은 맞아도 근거 경로가 설계 의도(관계 → 트리플 → 청크)와 달랐다. 링킹 수정(#47)이 Fast Path 를 항상 성공하게 만들어 드러남.
**참조**: `decisions/2026-11-14` D2 · `design/graph/design-graph-relation-targeting.md` · PR #49

### 유형 질문 = LLM 질의 계획(JSON) → 검증 → 결정적 SPARQL

**결정일**: 2026-11-14

**선택**: LLM 은 닫힌 경로 목록에서 질의 계획만 고르고, 검증·컴파일은 결정적으로. 표현 불가 질문만 C(LLM SPARQL).
**이유**: LLM 이 쓴 SPARQL 은 경로·문법 오류가 잦고 검증이 어렵다.
**주의**: 내부 경로는 AND 0건이면 조건별 OR 로 완화한다 (2026-11-15) — 외부 query_plan 은 완화하지 않는다 (2장).
**참조**: `decisions/2026-11-14` D3 · `2026-11-15` D9 · `design/graph/design-graph-class-query.md` · PR #51

### 다단계 질문 = 홉별 결정적 체인(H)

**결정일**: 2026-11-15 (보정 2026-11-17)

**선택**: LLM 은 홉 계획(관계·방향)만, 각 홉은 결정적 SPARQL. 0건이면 실제 관계 중 한 번 재선택. 그래프로 답할 수 없으면 C 대신 문서 검색(V).
**폐기한 것**: 다단계를 C(LLM SPARQL 생성)로 보내던 방식 — 다단계 0/10.
**11/17 보정**: '…은 무엇이며, 누가/언제/몇 년에' 도 다단계로 (Q36), 추가 속성 0건이면 재선택, '모두/나열' 질문은 두 엔티티 직접 관계로 끝내지 않음 (Q32).
**주의**: 체인 계획이 조건('할스테트 연구소의')을 홉으로 잡는 흔들림이 남아 있다 (Q35).
**참조**: `decisions/2026-11-15` D4·D5 · `2026-11-17` D8 · `design/graph/design-graph-multihop-chain.md` · PR #55 · cb8b03c

### 질문 분석 병합 (LLM 2회 → 1회) + 엔티티 역할·링킹 랭킹

**결정일**: 2026-07-17

**선택**: 엔티티 추출과 질문 분석을 한 호출로, 엔티티에 subject/object 역할, 멀티홉은 LLM `hop_count` 우선. 링킹은 완전일치 > 접두 > 부분포함.
**폐기한 것**: 조사 휴리스틱을 1차 신호로 쓰던 방식 (폴백으로 강등).
**주의**: 11/16 질의 계획 선행 실행·MCP 클라이언트 계획과 역할이 겹치는지 점검 필요.
**참조**: `decisions/2026-07-17` D2·D3 · `design/graph/design-query-analysis-merge.md` · PR #37

### 쿼리 생성 Inner/Outer Loop (LLM SPARQL 폴백 경로)

**결정일**: 2026-07-16

**선택**: LLM 생성 쿼리는 실패·0건이면 오류를 되먹여 최대 3회 재시도, 성공 쿼리는 동적 few-shot. 예시 저장은 Mongo + 인메모리 코사인.
**폐기한 것**: 예시를 Milvus 에 두는 하이브리드 안 (구현 중 번복 — 신규 컬렉션 load 가 이벤트 루프 동결).
**이후**: 11/14~15 관계 타게팅·유형 질의 계획·체인이 상위 경로가 되어, 이 루프는 C 경로에만 해당.
**참조**: `decisions/2026-07-17` D1 · `design/graph/design-query-generation-loop.md`

### 응답 속도 = 스트리밍 + 질의 계획 선행 실행

**결정일**: 2026-11-16

**선택**: `/chat/stream` SSE, 유형 질문의 질의 계획을 분석과 겹쳐 실행. 첫 글자 14.4초 → 약 9초.
**대가**: 외부 에이전트(MCP) 경로에서는 스트리밍 효과가 작다 — 내부 채팅용.
**참조**: `decisions/2026-11-16` D1 · PR #60

## 2. 외부 에이전트 (MCP · query_plan)

### 클라이언트가 query_plan 을 쓰고 RAGaaS 는 검증·컴파일·실행 (클라이언트 SPARQL 직접 생성 폐기)

**결정일**: 2026-11-16

**선택**: 클라이언트 에이전트가 describe 로 스키마를 받아 query_plan JSON 작성 → RAGaaS 는 LLM 없이 검증·SPARQL 컴파일·실행. 외부 계약은 query_plan 하나, 원문 SPARQL 은 관리자 전용. 사내 폐쇄망, 읽기 전용 + 범위·자원 제한. MCP `/api/mcp` + 스킬 `skills/ragaas-query`.
**이유**: 저장소(Fuseki → Neo4j)가 바뀌어도 클라이언트 무변경, 검증 가능, 안전.
**폐기한 것**: 클라이언트가 SPARQL 을 직접 생성 (사용자 제안을 검토 후 대체).
**왜 바꿨나**: 저장소 종속, 쓰기·과부하 위험, 검증 불가.
**참조**: **ADR-004** · `decisions/2026-11-16` D2 · `design/agent/design-mcp-agent-query.md` · PR #61

### query_plan 은 자동 완화하지 않고, 실패는 status: error

**결정일**: 2026-11-16

**선택**: 0건이면 `zero` + 이유. 조회 실패·시간 초과는 `error` (빈 결과로 숨기지 않음). 조건 상한 64, `in` 의 목록 밖 값은 빼고 평가 (GoJIRA 요청).
**이유**: 서버의 암묵적 완화는 답을 넓혀 오답이 된다. 부분 결과를 정답처럼 내면 클라이언트가 구분 못 한다.
**참조**: `decisions/2026-11-16` D3·D5

### query_plan 연도 조건

**결정일**: 2026-11-17

**선택**: 조건에 `year` (정수 또는 gte/lte) → 진술 연도로 거름. 연도 없는 진술로 빠진 엔티티 수를 `adjustments` 에 보고.
**참조**: `decisions/2026-11-17` D2 (5장 연도 항목)

**결정일**: 2026-11-15

**선택**: 사람이 핵심 관계 어휘(정의·방향)를 시드로 주고 기존 관계를 매핑, 정의 기반 재추출.
**폐기한 것**: 다양한 문서에 자동 유도 스키마만 쓰는 방식.
**왜 바꿨나**: 일반 동사 스키마('관련됨')가 되어 검색에 무용 — 자동 승격+재추출 12/39.
**참조**: `decisions/2026-11-15` D3 · PR #55 · 평가 README 3

### 재추출 시 domain 위반·근거 없는 트리플 제외

**결정일**: 2026-11-15

**선택**: 주어 클래스 ≠ domain 이면 버린다. 원문 근거 없는 목적어도 버린다.
**대가**: 정의가 domain 보다 넓은 관계의 사실이 **조용히** 버려진다 — 11/17 `기반함` (Q36).
**참조**: `decisions/2026-11-15` D7 · `2026-11-17` D4 · f7b442a

### 관계 domain 은 하나만 (다중 domain 적용 안 함)

**결정일**: 2026-11-17

**선택**: domain 은 클래스 하나. 정의가 더 넓으면 정의를 고치거나 개별 사실을 @add 로 고정.
**폐기한 것**: domain 을 여러 클래스로 허용하는 안 (검토 후 미채택).
**이유**: 목록은 OR/AND 가 모호하다. 엔티티당 클래스가 하나라 AND 는 만족 불가. RDF 의 `rdfs:domain` 여러 개는 교집합이라 OR 로 쓰면 TBox 의미가 틀어진다. 영향 범위가 넓다.
**미결**: `기반함` 정의의 '실험' 문구 정리.
**참조**: `decisions/2026-11-17` D5

### 트리플 추가 규칙(@add)

**결정일**: 2026-11-17

**선택**: 사람이 근거 청크·문서를 지정해 트리플을 규칙으로 고정 — 리플레이·재추출 뒤에도 유지. 기존 트리플 규칙(이동·삭제·뒤집기)에 추가.
**주의**: 화면 버튼 없음 (API `POST /schema/spec/triples/edit` action=add).
**참조**: `decisions/2026-11-17` D4 · c1ba9ed

### 사제 관계는 `지도교수_of` 정의를 지킨다

**결정일**: 2026-11-17

**선택**: 박사 지도·조수·박사후가 아닌 사제(스승 격·강의)는 넣지 않는다. 넓은 '가르침' 관계는 필요 시 별도.

## 반복되는 교훈

- **조용한 실패를 만들지 않는다.** 실패·제외는 결과에 드러나야 한다.
  - LLM 오류를 삼키는 폴백 제거 (07-05). WS 채널 키 불일치로 알림 미도달, 빈 값을 건너뛴 설정 오염 (07-15~17). 소스 일괄 동기화가 squash 머지에서 기능을 조용히 지움 (11-05).
  - Fuseki 쓰기 실패 은폐 → 재시도 후 FAILED (11/14).
  - `query_sparql` 이 시간 초과를 삼켜 부분 결과를 정답처럼 냄 → `status: error` (11/16).
  - 재추출 domain 검사가 정의상 맞는 사실을 말없이 버림 → Q36 (11/17). 연도 조건으로 빠진 엔티티는 수를 보고 (11/17).

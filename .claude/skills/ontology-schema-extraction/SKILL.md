# 온톨로지 스키마 추출

스키마는 "이 KB 에 올 질문을 그래프 경로로 답할 수 있게" 만드는 것이다. LLM 은 **모양**(클래스·관계·방향·정의)을 잘 내고,
**개별 엔티티 분류와 range 확인은 데이터로** 해야 한다. 절차는 *질문 → 시드 → 유도 → 데이터 검증 → 사람 검토 → 재추출 → 재측정*.

RAGaaS 에서의 구현 위치: 유도 프롬프트 `backend/app/services/schema_alignment/induction.py`(`build_induction_messages`),
데이터 검증 `schema_editor.range_check`, 편집기 Schema 탭(표·그래프·데이터 검증), 설계 `docs/design-schema-editor.md` §10.

## 1. 시작 전
1. 이 KB 에 올 질문 10~20개를 적는다. 질문의 대상 = 클래스, 대상 사이 연결 = 관계, 조건 값 = 값 속성.
2. 입력 종류를 가린다.
   - 구조화(YAML/JSON): 필드 구조를 결정적으로 옮긴다 (LLM 은 이름·설명만). 중첩 블록은 클래스가 아니라 속성 묶음,
     다른 레코드를 가리키는 필드는 관계.
   - 텍스트: LLM 유도. 가능하면 **시드 스키마**(클래스 이름·정의, 관계 이름·정의·domain·range)를 먼저 만든다 —
     시드가 있으면 방향·range 품질이 크게 좋아진다 (물리학사 test-ontology3).

## 2. 추출 규칙 (유도 프롬프트에 반영됨)
- **클래스**: 독립적으로 존재하고 여러 번 등장하는 대상의 종류. 영어 UpperCamelCase 단수 + 한 문장 정의.
  멤버는 주어뿐 아니라 **목적어로만 나오는 대상도** (예: 여러 관계의 목적어인 품질 속성).
  클래스가 아닌 것: 서술 문장, 점수·수치('-3점'), 한 대상에 붙은 속성 묶음, 지시어·일반명사 조각.
- **관계 vs 값 속성**: 목적어 대부분이 한 클래스의 멤버면 관계 → domain·range 를 준다. 목적어가 서술·수치·등급이면 값 속성(range 빈칸).
- **정의는 방향을 담아** `Domain | 관계 | Range — 한 문장` 으로. 수동태 문장은 능동으로 바꿔 판단.
- **이름**: 새 이름을 짓지 말고 기존 관계 중 가장 명확한 것을 대표로, 같은 의미만 별칭으로 묶는다.
- **부호·강도만 다른 관계 계열**(has_positive_effect_on / has_strong_negative_effect_on …)은 묶지 말고 같은 domain·range.
  하나로 합치려면 부호·강도를 담을 자리(reification)가 있어야 하므로, 평면 트리플 저장소에서는 하지 않는다.

## 3. 데이터 검증 (LLM 출력을 그대로 믿지 않는다)
| 검사 | 기준 | 실패하면 |
|---|---|---|
| range 일치율 | 서로 다른 목적어(서술·수치 제외) 5개 이상, 60% 이상이 range 클래스 멤버 | 데이터가 다른 클래스를 60%↑ 지지하면 교체, 30% 미만이면 비움(사람·시드 선언은 경고만) |
| 멤버 누락 | range 클래스로 이어지는데 클래스가 없는 목적어 | 후보로 제안 → 사람이 체크 → class 규칙 + 리플레이 |
| range 위반 | 목적어가 다른 클래스 멤버 | 방향이 뒤집혔거나 분류가 틀림 — 확인 |
| 표기 중복 | 한 클래스 안의 한·영·약어 표기 (scalability / 확장성) | 클래스 범위 LLM 제안 → 사람이 체크 → entity 규칙 |
| 근거 | 목적어 핵심어가 원문에 있음 | 재추출 단계에서 버림 (`is_grounded`) |
| domain 위반 | 주어 클래스가 domain 과 다름 | 재추출 단계에서 방향 교정·제외 (`check_domain`) |

계열(부호·강도)은 목적어를 합쳐 판정한다 — 한쪽 목적어만 분류돼 있어도 계열 전체가 같은 range 를 받는다.

## 4. 순서와 확인
1. 질문 목록 + (텍스트면) 시드
2. 유도 — 평가에 쓰는 KB 는 먼저 **미리보기(dry-run)** 로 차이만 본다 (`POST /knowledge-bases/{kb}/schema/induce/dry-run`)
3. 적용 → 리플레이 뒤 range 검증이 자동으로 돈다
4. 편집기 Schema 탭: 그래프로 고립 클래스·'domain 미지정'·자기 관계 확인, 데이터 검증 카드에서 멤버 누락 지정·표기 병합
5. 확정 → 스키마 기준 재추출(비용 있음) → 3절 다시 측정, 전후 비교
6. 질문 세트로 검색 평가 — LLM 비결정성 때문에 **2회 이상** 평균

## 5. 하지 말 것
- 제안 자동 수락 (멤버 누락·표기 병합은 사람이 체크)
- 1글자 이름을 정규화 키로 그냥 쓰기 — 빈 키 충돌로 한 규칙이 모든 1글자 엔티티에 번진다 (고쳐짐, 회귀 주의)
- 평가용 KB 를 미리보기 없이 재유도
- 평면 트리플에서 관계 병합으로 부호·강도 정보를 잃기
